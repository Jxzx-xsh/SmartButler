# 采集端配置 — Android 手机（坚果 Pro 2 / Android 7）

> 第一版采集节点用闲置 Android 手机 + 现成推流 App，不刷机、不自写 App、不用开发板。门控（移动侦测 + VAD）放在 Mac mini 侧。本文档说明手机端 App 的安装与配置。

## 1. 兼容性结论

坚果 Pro 2 是 Android 7（API 24）。主流推流 App 最低支持版本普遍在 Android 4.x~5.x，**Android 7 完全在覆盖范围内，能安装能用**。

真正受 Android 7 限制的是"自写 App 用新版 WebRTC / CameraX"那条路——而第一版走现成 App，不受影响。

## 2. 推荐 App（均支持 Android 7）

| App | 支持版本 | 推流协议 | 特点 | 用途 |
| --- | --- | --- | --- | --- |
| **IP Webcam（首选）** | Android 4.1+ | MJPEG(HTTP) / RTSP | 视频 + 音频，自带基础移动侦测、分辨率/码率/夜间模式等设置，免费版够用 | Task 6 网关首选对接 |
| **Larix Broadcaster** | Android 5+ | RTSP / RTMP / SRT | 专业推流，画质与稳定性好 | 想要更稳推流时的备选 |
| **RTSP Camera Server 等** | 视 App 而定 | RTSP | 功能类似的 RTSP 推流 | 备选 |

## 3. 安装注意事项（Android 7）

1. **安装来源**
   - 能上 Google Play：直接搜索安装最省心。
   - Play 不可用（国内常见）：从 APKMirror 等站侧载 APK。注意**选标注支持 Android 7 / arm64 的版本**；App 的"最新版"有时提高了最低系统要求导致装不上，退一个较早版本即可。
2. **后台保活**：Android 7 省电策略可能杀后台。进「设置 → 电池 → 应用优化」把该 App 设为「不优化 / 允许后台运行」。
3. **常供电 + 散热**：固定当采集节点用，保持常供电；老机型长时间推流会发热，注意散热、别捂着。
4. **屏幕策略**：设置里开启「锁屏仍推流 / 屏幕关闭继续运行」，避免息屏断流。
5. **局域网固定 IP**：在路由器为这台手机绑定固定内网 IP（或 DHCP 保留），避免拉流地址变化。

## 4. 用 IP Webcam 快速验证推流（最省心路径）

1. 手机安装并打开 **IP Webcam**。
2. 按需设置分辨率、码率（第一版建议 640×480 ~ 1280×720，码率 1~2 Mbps，够识别物品即可，别太高）。
3. 开启音频（Audio mode 选 enabled），滑到底点「Start server」。
4. App 顶部会显示一个地址，形如 `http://<手机内网IP>:8080`。
5. 在 Mac mini 浏览器打开该地址 → 看到实时画面即说明推流已通。
   - MJPEG 视频流通常是 `http://<手机IP>:8080/video`
   - RTSP 地址通常是 `rtsp://<手机IP>:8080/h264_ulaw.sdp`（具体以 App 页面显示为准）
6. 记下这个地址，Task 6 的 Mac mini 采集网关将用 ffmpeg 拉这个流。

## 5. 与后续任务的衔接

- **Task 6（采集网关）**：Mac mini 用 ffmpeg 拉上面的 RTSP/MJPEG 地址，解复用为视频帧 + 音频 PCM 两路。
- **Task 7（门控）**：在网关输出上做移动侦测 + VAD，有变化才产生分析事件。因此手机端只需持续推流，无需在手机上做移动侦测（即便 IP Webcam 自带移动侦测，第一版也以 Mac mini 侧门控为准，可关闭 App 侧侦测以简化）。

## 6. 省电/稳定建议（长期固定运行）

- 用一个支持长期供电的充电器，避免边充边高负载导致电池鼓包风险；有条件可找能"仅供电不充满电"的方案延长电池寿命。
- 固定支架朝向冰箱 / 操作台 / 想监控的区域。
- 定期检查推流是否存活（Task 12 的整合阶段会在后端加采集源健康检查与断线重连）。

## 7. iOS / iPhone 测试

iPhone 可以用来**快速验证推流链路**。对 Mac mini 端网关而言，流就是流，不区分 Android 还是 iOS，只要能推出 RTSP/MJPEG，网关一样能拉。

### 推荐 App（iOS）

| App | 模式 | 协议 | 说明 |
| --- | --- | --- | --- |
| **IP Camera Lite / IPCamera（验证首选）** | pull（手机当服务器） | MJPEG / RTSP | 类似 Android 的 IP Webcam，Mac 浏览器直接打开地址即可看，验证最直观 |
| **Larix Broadcaster** | push（主动推流） | RTSP / RTMP / SRT | 免费、专业、画质稳，与 Android 版同一家，跨平台一致 |
| nanoStream / Live:Air 等 | push | RTMP / RTSP | 更专业的直播推流，备选 |

### 两种模式与网关适配

- **pull 模式**（手机起服务器，Mac 去拉）：如 IP Camera Lite。Mac 浏览器打开 `http://<iPhone内网IP>:<端口>` 就能看，验证最简单。
- **push 模式**（手机往外推）：如 Larix。需要一个接收端——最快是等 Task 6 的网关用 ffmpeg 接；想现在就试，可在 Mac 上跑一条 ffmpeg/简单 RTSP/RTMP 接收命令。

两种模式 Task 6 的网关都能适配。

### 最省心的即时验证路径（iPhone）

1. App Store 安装 **IP Camera Lite**（pull 模式）。
2. 启动，App 显示 `http://<iPhone内网IP>:<端口>` 地址。
3. Mac 浏览器打开该地址，看到实时画面即说明链路通。
4. 这个地址 Task 6 的网关可直接用 ffmpeg 拉。

### 重要提醒：测试用 iPhone，长期部署用坚果 Pro 2

iPhone 适合**现在快速验证链路**，但不适合当**长期固定采集节点**（平时要用 iPhone，不可能一直架着推流）。建议：

- 用 **iPhone 先把"推流 → Mac 网关接收 → 识别"链路跑通测试**。
- **长期固定部署仍用闲置的坚果 Pro 2**（Android 7 + IP Webcam，见本文档第 2~6 节）。
