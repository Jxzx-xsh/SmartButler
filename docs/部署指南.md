# SmartButler 部署指南

> 本文档说明如何在一台 Mac mini 上完整部署 SmartButler：后端 API、PWA 前端、本地大模型、语音转写、采集网关与 Home Assistant 集成。架构与任务拆分见文末互链的[技术方案](技术方案.md)，采集手机端配置见[采集端配置](采集端配置.md)，本文不重复其内容。

全程本地运行、注重隐私，核心用途是记录家庭食材 / 物品及其到期时间并做到期提醒。

## 1. 前置依赖

| 依赖 | 版本 / 说明 | 用途 |
| --- | --- | --- |
| Node.js | **v22+**（建议 v22.9.0 以上） | 运行后端与前端构建。启动脚本用到 Node 原生 `--env-file-if-exists` 标志注入 `.env`，该标志为 v22.9.0+ 新增 |
| npm | 随 Node 附带 | 安装依赖、跑脚本 |
| ffmpeg | 建议走 Homebrew（`brew install ffmpeg`，默认在 `/opt/homebrew/bin/ffmpeg`） | 采集网关拉手机 RTSP / MJPEG 流并解复用 |
| whisper.cpp | `whisper-cli`（`brew install whisper-cpp`，默认在 `/opt/homebrew/bin/whisper-cli`） | 本地语音转写（STT） |
| whisper 模型 | ggml `.bin`（非 GGUF），默认 `backend/models/ggml-small.bin` | whisper.cpp 加载的模型文件 |
| LM Studio | 本地运行，暴露 OpenAI 兼容端点（默认 `http://localhost:1234/v1`） | 文本 / 视觉 / 嵌入推理 |
| Home Assistant | 可选 | 双向集成（读状态、控设备、订阅事件） |

LM Studio 需加载三类模型（模型 id 对应 `backend/.env.example` 默认值，按需在 `.env` 覆盖）：

- 文本对话：`qwen/qwen3-4b-2507`（`LMSTUDIO_TEXT_MODEL`）
- 视觉识别：`qwen/qwen3-vl-8b`（`LMSTUDIO_VISION_MODEL`）
- 向量嵌入：`text-embedding-nomic-embed-text-v1.5`（`LMSTUDIO_EMBED_MODEL`）

LM Studio、HA 未启动时所有相关端点都会优雅降级（不崩），可先把核心食材管理闭环跑起来，再逐步接入。

## 2. 配置

后端配置集中在环境变量，统一经 `backend/.env` 注入；未覆盖的项用代码内置默认值。

1. 复制示例文件并按需填写：

   ```bash
   cp backend/.env.example backend/.env
   ```

   `backend/.env.example` 列出全部变量（含中文注释与默认值），分组为：通用（`SMARTBUTLER_PORT`、`SMARTBUTLER_DB_PATH`）、LM Studio（`LMSTUDIO_*`）、whisper.cpp（`WHISPER_*`）、采集网关（`CAPTURE_*`）、门控移动侦测（`MOTION_*`）、门控 VAD（`VAD_*`）、Home Assistant（`HA_*`）。`.env` 含真实配置 / 令牌，已被 git 忽略，切勿提交。

2. Home Assistant（可选）：在 HA 用户资料页（个人资料 → 底部「长期访问令牌」→「创建令牌」）生成长期访问令牌，填入 `backend/.env`：

   ```ini
   HA_BASE_URL=http://<ha-host>:8123
   HA_TOKEN=<你的长期访问令牌>
   ```

   `HA_BASE_URL` 留空即视为未配置，HA 相关端点优雅降级。`HA_WS_URL` 留空时会从非空 `HA_BASE_URL` 自动推导。

3. 前端：复制 `pwa/.env.example` 为 `pwa/.env`，`VITE_API_BASE` 指向后端地址（默认 `http://localhost:3000`）。供手机 / 局域网访问时改成 Mac mini 的内网地址，例如 `http://<mac-mini-内网IP>:3000`。

## 3. 启动步骤

### 3.1 安装依赖

根目录一次装齐根级编排依赖，再分别装后端与前端：

```bash
npm install                 # 根级（concurrently 等编排依赖）
npm --prefix backend install
npm --prefix pwa install
```

### 3.2 初始化数据库（首次）

```bash
npm run db:init             # 建表（幂等）
npm run db:seed             # 可选：灌入示例分类 / 食材
```

根脚本转调 `npm --prefix backend run db:init` / `db:seed`，二者已带 `--env-file-if-exists=.env`。

### 3.3 启动后端与前端

一键方式（二选一）：

```bash
# 方式 A：根 package.json 的 concurrently 编排，带 backend / pwa 前缀标签
npm run dev

# 方式 B：纯 shell 脚本，Ctrl-C 可干净退出、不留僵尸进程
bash scripts/start-dev.sh
```

分开手动启动：

```bash
# 后端（默认监听 0.0.0.0:3000，SMARTBUTLER_PORT 可覆盖）
npm --prefix backend run dev

# 前端 dev（带 --host，便于局域网 / 手机访问）
npm --prefix pwa run dev -- --host
```

`--host` 让 Vite 监听所有网卡地址，手机 / 其他设备才能通过 Mac mini 内网 IP 打开 PWA。

### 3.4 打开 PWA

浏览器访问 Vite 输出的地址（默认 `http://localhost:5173`；带 `--host` 时还会打印内网地址）。PWA 可安装到桌面 / 主屏，离线可用。

### 3.5 生产构建（可选）

```bash
npm run build               # 顺序构建：先 backend（tsc）后 pwa（tsc -b && vite build）
npm --prefix backend run start   # 以 dist/server.js 启动后端
```

## 4. 三条录入渠道

核心是把食材 / 物品及到期时间记录进来，共三条渠道：

1. **手动录入**：在 PWA 表单里增删改查物品，临期在看板高亮。这是最直接的食材管理闭环。
2. **语音录入**：
   - 上传音频转写入库：`POST /api/voice/ingest`（multipart 上传音频文件 → whisper 转写 → LM Studio 结构化解析 → 入库）。
   - 直接文本入库（可脱离 whisper 联调）：`POST /api/voice/ingest-text`，body `{"text": "我买了两盒牛奶，保质期到下周五"}`。
3. **视觉录入**：`POST /api/vision/ingest-frame`（接收 multipart 图片文件或 base64 帧 → LM Studio 视觉模型识别物品 / 估计到期 → 入库，低置信标记待确认）。

## 5. 监控

手机作为采集节点持续推流，Mac mini 侧采集网关接流后可在 PWA 查看实时画面：

1. 手机用现成推流 App 推 RTSP / MJPEG 视频 + 音频到局域网（App 安装与地址获取见[采集端配置](采集端配置.md)）。
2. 启动采集：`POST /api/capture/start`，body `{"url": "http://<手机IP>:8080/video"}`（也可在 `backend/.env` 设 `CAPTURE_SOURCE_URL`，非空时后端启动即自动拉流）。
3. 查看状态：`GET /api/capture/status`；PWA 经 `GET /api/capture/stream` 看实时画面；`GET /api/capture/snapshot` 取最近一帧。
4. 停止采集：`POST /api/capture/stop`。

门控（移动侦测 + VAD）在网关输出上运行，仅在有变化时触发分析，灵敏度经 `MOTION_*` / `VAD_*` 环境变量调节；门控统计见 `GET /api/gating/status`。

## 6. Home Assistant 集成

1. 按[第 2 节](#2-配置)配好 `HA_BASE_URL` 与 `HA_TOKEN`。
2. 探测连通：`GET /api/ha/status`（未配置返回 `{ "configured": false }`，已配置返回可达 / 连接状态）。
3. 读写实体：`GET /api/ha/states` 读全部状态；`POST /api/ha/service` 调用 HA 服务控制设备。
4. 暴露临期：`POST /api/ha/expose-expiring` 把临期统计写成 HA 传感器，供自动化 / 通知消费。
5. 用自然语言控设备：`POST /api/command`（见下一节）。

## 7. 指令路由

`POST /api/command` 接收一句中文指令，body `{"text": "...", "source": "voice" | "manual"}`（`source` 可选）。后端先用意图分类器分类，再分流到四类处理：

| 意图 | 说明 | 示例 |
| --- | --- | --- |
| `immediate_action` | 立即控制设备 → 调 HA 开 / 关（HA 未配置优雅降级，不执行只提示） | 「关掉客厅灯」 |
| `item_record` | 记录物品 → 解析后入库 | 「冰箱里还有三个鸡蛋」 |
| `query` | 查询 → 返回临期物品列表（3 天内） | 「还有什么快过期了」 |
| `unknown` | 无法识别 → 友好提示，不执行 | 无关 / 模糊语句 |

每次路由都会写一条行为日志（`eventLogs`，`source='command'`），为后续习惯学习沉淀数据。

## 8. API 速查表

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/items` | 物品列表（支持 categoryId / location / confirmed 过滤，附带距到期天数） |
| GET | `/api/items/expiring` | N 天内到期（含已过期）清单，核心到期提醒端点 |
| GET | `/api/items/:id` | 单个物品详情（不存在 404） |
| POST | `/api/items` | 创建物品（成功 201） |
| PATCH | `/api/items/:id` | 部分更新物品 |
| DELETE | `/api/items/:id` | 删除物品（成功 204） |
| GET | `/api/categories` | 列出所有分类 |
| POST | `/api/categories` | 创建分类（撞唯一约束 409） |
| GET | `/api/ai/health` | 探测 LM Studio 是否可达并返回可用模型 |
| POST | `/api/voice/ingest-text` | 文本直接解析入库（脱离 whisper 联调） |
| POST | `/api/voice/ingest` | 上传音频 → 转写 → 解析 → 入库 |
| POST | `/api/vision/ingest-frame` | 接收图片 / base64 帧 → 视觉识别 → 入库 |
| GET | `/api/vision/status` | 视觉入库统计 |
| GET | `/api/capture/status` | 采集网关状态 + 是否已配置源 |
| POST | `/api/capture/start` | 切换采集源并启动拉流 |
| POST | `/api/capture/stop` | 停止采集 |
| GET | `/api/capture/snapshot` | 返回最近一帧 JPEG（无帧 503） |
| POST | `/api/capture/talk` | 上行通话录音留存（写临时文件 + 落库） |
| GET | `/api/capture/stream` | MJPEG 实时画面推送 |
| GET | `/api/gating/status` | 门控统计 + 是否正在活动中 |
| GET | `/api/ha/status` | HA 配置 / 可达 / 连接状态探测（未配置返回 configured:false） |
| GET | `/api/ha/states` | 读取全部 HA 实体状态 |
| POST | `/api/ha/service` | 调用 HA 服务控制实体 |
| POST | `/api/ha/expose-expiring` | 把临期统计暴露为 HA 传感器 |
| POST | `/api/command` | 路由一句中文指令（四类意图分流） |
